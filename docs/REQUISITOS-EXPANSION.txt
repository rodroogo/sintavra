# EXPANSIÓN DE SINTAVRA — PLATAFORMA COMPLETA

Quiero ampliar Sintavra para que no sea simplemente una colección de cursos.

Debe sentirse como una plataforma completa de aprendizaje y desarrollo de software.

Toda la aplicación debe estar conectada entre sí.

NO crear páginas aisladas.
NO crear botones falsos.
NO crear secciones visuales sin funcionalidad.
NO utilizar datos simulados como si fueran reales.

La estructura principal será:

SINTAVRA
├── Inicio
├── Aprender
├── Categorías
├── Mis proyectos
├── Terminal
├── Playground
├── Progreso
├── Perfil
└── Ajustes

Utilizar:

TEORÍA
↓
EJEMPLO
↓
EXPLICACIÓN INTERACTIVA
↓
EJERCICIO
↓

↓
MINIPROYECTO

Módulo:

“Contador inteligente”

- utilice un loop
- procese valores
- muestre resultados

Dificultad del proyecto proporcional al módulo.

proyectos pequeños.

Intermedio:
proyectos con varias partes.

Avanzado:
proyectos completos.

==================================================
7. EXPLICACIÓN DE CÓDIGO
==================================================

Mantener la filosofía principal de Sintavra.

El usuario debe poder pulsar partes del código.

Ejemplo:

def

Al pulsarlo:

────────────────────

def

Sirve para definir una función.

Ejemplo:

def saludar():
    print("Hola")

En conjunto:

def + nombre + () + :

crean una función.

[Entendido]

────────────────────

Lo mismo con:

if
else
elif
for
while
return
import
#include
class
public
private
etc.

NO explicar únicamente palabras individuales.

También explicar cómo funcionan EN CONJUNTO.

31. REGLA FINAL
==================================================

Analiza primero el código existente de Sintavra.

NO reconstruyas innecesariamente partes que ya funcionan.

NO elimines características existentes.

NO reemplaces código funcional por placeholders.

NO rompas compatibilidad.

Antes de modificar:

1. analiza arquitectura actual
2. identifica componentes existentes
3. identifica base de datos
4. identifica autenticación
5. identifica sistema educativo
6. crea plan de migración
7. implementa progresivamente
8. prueba cada flujo

Al terminar cada fase:

- ejecutar tests
- revisar errores TypeScript
- revisar consola
- probar responsive
- probar navegación
- comprobar persistencia
- comprobar autenticación
- comprobar permisos

No consideres una característica terminada solamente porque visualmente existe.

Una característica está terminada cuando FUNCIONA.
