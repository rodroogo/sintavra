SINTAVRA — ESPECIFICACIÓN MAESTRA

Quiero que diseñes y desarrolles Sintavra, una plataforma completa para aprender programación mediante teoría, práctica, proyectos, experimentación y un tutor de inteligencia artificial.

Sintavra NO debe ser una demo, landing page, chatbot disfrazado de plataforma educativa ni un conjunto de pantallas falsas.

Debe ser un producto funcional, mantenible, escalable, seguro, visualmente excelente y preparado desde el principio para funcionar como:

- Aplicación web
- Aplicación de escritorio
- Futuro CLI
- Plataforma educativa extensible

Nombre:

Sintavra

Lema:

Aprende. Programa. Comprende.

Principio fundamental:

«La IA debe enseñar al usuario a programar, no programar por él.»

---

1. IDENTIDAD DEL PRODUCTO

Sintavra debe sentirse como un producto diseñado cuidadosamente por personas.

NO quiero la apariencia típica de una aplicación generada automáticamente por IA.

Evitar específicamente:

- Landing pages genéricas
- Gradientes puestos sin propósito
- Exceso de tarjetas redondeadas
- Glassmorphism innecesario
- Textos exageradamente promocionales
- Emojis por todas partes
- Secciones repetitivas
- Espaciados absurdamente grandes
- Animaciones simplemente decorativas
- Botones gigantes
- Dashboards genéricos
- Componentes que parezcan sacados directamente de una plantilla
- Textos artificiales
- Nombres genéricos como "AI Learning Experience"
- Datos falsos utilizados para aparentar funcionalidad

Quiero que cada pantalla parezca diseñada deliberadamente para Sintavra.

Debe existir consistencia en:

- Espaciado
- Tipografía
- Iconografía
- Navegación
- Estados
- Colores
- Animaciones
- Terminología
- Mensajes de error
- Componentes
- Interacciones

La interfaz debe sentirse natural y profesional.

---

2. ESCALA DEL PROYECTO

El objetivo a largo plazo es que Sintavra pueda convertirse en un proyecto extremadamente completo, potencialmente superior a 300 000 líneas útiles entre código, tests, contenido educativo estructurado, documentación y herramientas internas.

IMPORTANTE:

NO alcanzar esta cifra artificialmente.

Está terminantemente prohibido aumentar el número de líneas mediante:

- Código duplicado
- Comentarios inútiles
- Archivos generados artificialmente
- Datos falsos
- Funciones repetidas
- Componentes duplicados
- Espacios o saltos de línea innecesarios
- Código muerto
- Dependencias copiadas al repositorio
- Archivos minificados
- Builds
- node_modules
- Código generado automáticamente contabilizado como trabajo propio
- Miles de ejercicios repetidos con cambios mínimos

La calidad arquitectónica tiene prioridad absoluta sobre el número de líneas.

Si Sintavra necesita 300 000+ líneas para alcanzar su visión completa, deben existir porque el producto realmente contiene esa funcionalidad.

No sacrificar mantenibilidad para cumplir una métrica.

7. APRENDIZAJE ENTRE LENGUAJES

Sintavra debe aprovechar conocimientos anteriores.

Si alguien sabe Python y comienza C++, puede mostrar equivalencias.

Python:

for i in range(5):

C++:

for (int i = 0; i < 5; i++)

No asumir que dos conceptos son idénticos solamente porque parecen similares.

Explicar también diferencias importantes.

10. PISTAS PROGRESIVAS

Ejemplo:

Código:

for (int i = 0; i < 10; i+)

PISTA 1:

Observa qué debería ocurrir con "i" después de cada iteración.

PISTA 2:

Necesitas incrementar "i".

PISTA 3:

Revisa el operador "++".

Después de intentos suficientes puede explicar la solución completa.

40. TEXTO HUMANO

Todo el copy debe sonar natural.

Evitar frases genéricas típicas como:

"Embark on your coding journey."

"Unlock your potential."

"Revolutionize your learning."

"Powered by cutting-edge AI."

Si con el tiempo el proyecto supera 300 000 líneas útiles, perfecto.

elimínalo.
